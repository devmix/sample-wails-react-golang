# Frontend Conventions

## Tailwind CSS v4

### Configuration

No `tailwind.config.js`. Tailwind v4 uses CSS-first configuration via `@theme inline` in `index.css`:

```css
@import "tailwindcss";

@theme inline {
  --color-background: var(--background);
  --color-primary: var(--primary);
  /* ... */
}
```

### Dark mode

Custom variant defined in CSS:
```css
@custom-variant dark (&:is(.dark *));
```

Usage in components: `dark:bg-card` or conditional class on `<html>` element.

### Theme tokens

All colors use OKLCH color space for perceptual uniformity. Priority and tag colors are custom tokens mapped through `@theme inline`.

## shadcn/ui Components

Base components live in `frontend/src/components/ui/`. Built on Radix UI primitives with CVA (`class-variance-authority`) for variant management.

### Component variants

| Component | Variants |
|-----------|----------|
| Button | default, destructive, outline, secondary, ghost, link |
| Badge | default, secondary, destructive |
| Card | Card, CardHeader, CardContent, CardFooter (composable) |

### Adding new shadcn components

Use the shadcn CLI or manually create following existing patterns:
1. Import Radix primitive from `@radix-ui/react-*`
2. Define variants with CVA (`cva()`)
3. Export component with `cn()` for class merging
4. Use `React.forwardRef` for proper ref forwarding

## Path Aliases

Configured in both `tsconfig.json` and `vite.config.ts`:

| Alias | Resolves to | Usage |
|-------|-------------|-------|
| `@/*` | `frontend/src/*` | `import { Button } from '@/components/ui/button'` |
| `@bindings/*` | `frontend/bindings/*` | `import * as TodoService from '@bindings/...'` |

### tsconfig.json key settings

```json
{
  "compilerOptions": {
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": false,
    "noImplicitAny": false,
    "moduleResolution": "bundler",
    "jsx": "react-jsx"
  }
}
```

## Auto-generated Bindings

`frontend/bindings/` is generated by Wails vite plugin on each dev/build cycle.

### Import pattern

Hooks import services from bindings:
```typescript
import * as TodoService from '@bindings/sample-wails-react-golang/internal/app/service/todoservice';
```

Types are re-exported through `types/models.ts`:
```typescript
export type { Todo, Note, Tag, ... } from '@bindings/.../model/models';
```

**Never edit files in `frontend/bindings/` manually.**

## Utility Functions

### cn() (`lib/utils.ts`)

Combines `clsx` + `tailwind-merge` for safe class merging with Tailwind:
```typescript
import { cn } from '@/lib/utils';
// Usage: cn("base-class", variant === "destructive" && "bg-red-500")
```

### debounce (`utils/debounce.ts`)

Throttles rapid input events (used by SearchBar for search queries).

## Package Management

`.npmrc` enforces `minimum-release-age=10080` (7 days) to avoid freshly compromised packages. Honored by pnpm and bun; harmless with npm.

```
minimum-release-age=10080
```

## State Management

React hooks only — no Redux, Zustand, or external state library. Component state via `useState`, shared logic extracted into custom hooks (`useTodos`, `useNotes`, `useTags`).

### Hook pattern

Each hook follows a consistent structure:
1. Local state with `useState` (data, loading, error)
2. Fetch on mount with `useEffect`
3. CRUD methods as async functions that update local state optimistically
4. Normalization function to handle null/undefined from bindings
